# B-design Agent 组件规范

本规范由 `references/B-design/` 中的 PDF 入库生成，适用于 Agent 任务执行、生成中卡片、状态栏、任务规划、任务节点、数据收集和深度思考等组件的设计审核。

## 通用审核原则

- 审核时必须依据本文件中的规范文本，不要套用其他设计体系的色彩、按钮、标签等无关规范。
- 标题、内文描述是强规则来源；浅灰底或页面内嵌 UI 图片是规范示意图和案例素材。
- 对只有标题和示意图的页面，按标题识别组件状态，把示意图作为该状态的视觉参考；不要凭视觉图臆造未标注的精确尺寸。
- 对「必有」项，若被审核图片中对应组件缺失该元素，应输出问题和修改建议。
- 对「可选」项，除非业务上下文明确需要，否则不要因为缺失直接判定违规。
- 对状态类组件，重点检查状态文案、状态图标、展开/收起、停止/失败/已完成等状态是否与当前任务阶段一致。
- 对生成中卡片，重点检查卡片标题、补充文案、生成内容、主按钮、次按钮、延展操作区和最大高度。
- 输出修改建议时，应指向具体组件和状态，并优先引用本规范里的组件名称，例如「任务规划」「数据收集」「生成中卡片-表格」。

## 任务规划

### 审核方式
- 仅当被审核图片中出现「任务规划」或其同类 Agent 组件时适用。
- 优先检查规范文本中的「必有」项、状态文案、展开/收起交互、主次操作和容器高度。
- 规范写明「可选」的元素不能因为缺失直接判定违规；只有业务场景需要但设计缺失时才作为问题。
- 标题加示意图的页面代表该状态或结构的标准视觉参考。没有明确尺寸标注时，不要把示意图中的像素值当作硬性尺寸。

### 规范文本
任务规划
智能体将复杂任务分解为一系列可执行的步骤，帮助用户建立预期并了解任务全貌

何时使用
浏览类：任务开始前，向用户展示完整的执行计划以供预览或确认

节点类：任务执行过程中，实时指示当前进度与后续步骤，可与任务节点搭配使用

组件构成
任务规划组件包括标题、展开收起按钮和内容 3部分

1、标题：必有，表示卡片状态，浏览类包括生成中、已生成 2 种状态，节点类包括生成中、已
生成、进行中、已完成 4种状态
2、展开收起按钮：必有，用户可点击
3、大纲内容：必有，结构化展示任务步骤

浏览类
浏览类任务规划组件包括生成中、已生成2种状态，向用户展示完整的执行计划以供预览和确认

生成中
内容逐行出现，卡片高度随文字内容高度变化，不限高，用户可手动点击收起，点击收起时为
「收起态」

已生成
默认为展开状态，步骤名称尽量限制在1行内，具体任务内容结构化展示，用户可手动点击收
起，点击收起时为「收起态」

节点类
节点类任务规划组件包括生成中、已生成、进行中、已完成4种状态，实时指示当前进度

生成中
内容逐行出现，卡片高度随文字内容高度变化，不限高，用户可手动点击收起，点击收起时为
「收起态」

已生成
展示全部步骤节点，标题位置展示任务步骤数量，不限高，用户可手动点击收起，点击收起时为
「收起态」

进行中
标题位置展示当前步骤数/总步骤数，节点状态与生成链状态一致，进行中的收起态展示当前节点

大纲和节点状态对应，包括已完成、进行中、待完成、任务终止、任务失败

已完成

默认为展开状态，所有节点均为已完成状态，任务标题变为“任务已完成”

## 任务节点

### 审核方式
- 仅当被审核图片中出现「任务节点」或其同类 Agent 组件时适用。
- 优先检查规范文本中的「必有」项、状态文案、展开/收起交互、主次操作和容器高度。
- 规范写明「可选」的元素不能因为缺失直接判定违规；只有业务场景需要但设计缺失时才作为问题。
- 标题加示意图的页面代表该状态或结构的标准视觉参考。没有明确尺寸标注时，不要把示意图中的像素值当作硬性尺寸。

### 规范文本
任务节点
呈现智能体执行任务时的节点及状态，向用户展示任务流程

何时使用
智能体按步骤执行具体任务时，以生成链呈现当前任务节点及状态，向用户展示清晰明确的生成
流程

组件构成
任务节点包含一级节点、二级节点，框架上用虚线表示从属关系

1、一级节点：必有，包含节点状态、节点名称、展开收起按钮
2、二级节点：必有，包含节点状态、节点内容

一级节点
一级节点包括节点状态、节点名称、展开收起按钮3部分

1、节点状态：必有，表示当前节点状态，包括进行中、已完成、生成失败
2、节点名称：必有，当前任务步骤名称
3、展开收起按钮：可选，用户可点击

组件状态

生成中

当前一级节点下的二级节点任务正在进行中，或当前一级节点下有待用户确认的内容

已完成

当前一级节点下所有二级节点均已完成

已终止

用户主动终止任务

生成失败

当前一级节点下有二级节点任务失败，具体失败原因展示在二级节点中，一级节点仅状态icon变
化

二级节点

二级节点包括节点状态、节点名称、拓展内容。

1、节点状态：必有，表示当前节点状态
2、节点名称：必有，当前任务步骤名称，文案与状态统一
3、拓展内容：可选，可展示当前任务节点生成的文件、任务进度等内容

组件状态

生成中

当前任务正在进行中，文案为「正在XXX」，有进度的节点可展示当前任务进度

已完成

当前节点已完成，文案为“已完成 XXX”

任务终止

用户主动终止任务

生成失败

当前节点任务失败，文字展示具体失败原因

任务节点和任务规划搭配使用
并列窗口或主次窗口模式中，可在对话窗口使用节点类任务规划组件表示任务进度，同时在工程/
进展窗口以任务节点展示详细进度，两个窗口的节点状态一致

任务规划节点状态
大纲和节点状态对应，包括已完成、进行中、待完成、任务终止、任务失败

已完成

进行中

待完成

任务终止

任务失败

## 数据收集

### 审核方式
- 仅当被审核图片中出现「数据收集」或其同类 Agent 组件时适用。
- 优先检查规范文本中的「必有」项、状态文案、展开/收起交互、主次操作和容器高度。
- 规范写明「可选」的元素不能因为缺失直接判定违规；只有业务场景需要但设计缺失时才作为问题。
- 标题加示意图的页面代表该状态或结构的标准视觉参考。没有明确尺寸标注时，不要把示意图中的像素值当作硬性尺寸。

### 规范文本
数据收集
智能体自动获取内/外部数据信息，并进行提炼与总结，为其输出结论提供事实与数据支
撑

何时使用
当AI的回答需要依赖实时、外部的或特定的内部系统数据作为佐证时，用于自动完成信息
的搜集、分析与呈现

组件构成
数据收集组件包括状态、展开收起按钮和内容3部分，内容分为节点标识、节点说明、执
行内容三部分

1、必有，随状态变化，包括搜索和分析资料中、已完成搜索和分析资料、已停止搜索和
分析资料
2、展开收起按钮：必有，用户可点击
3、内容：可选，收起态时不展示

1、节点标识：必有，表示当前节点内容，如搜索、阅读等
2、节点说明：必有，说明当前节点完成的任务
3、执行内容：可选，展示具体的搜索内容、执行情况等

组件状态
数据收集共有3种不同状态，分别为：搜索和分析资料中、已完成搜索和分析资料、已停
止搜索和分析资料

搜集和分析资料中
智能体正在输出搜索和阅读的内容，文字扫光动效，内容逐字出现，卡片高度随文字内容
高度变化，内容区最大高度300px。用户可手动点击卡片头部或「收起」按钮，点击后卡
片变为「收起态」

已完成

数据收集及分析完成后自动收起，用户可手动点击卡片头部或「展开」按钮，点击后卡片
变为「展开态」，状态变为“已完成搜索和分析资料”，已完成状态不限制卡片高度，收
起状态时展示收集资料数量

已停止
收集和分析过程中用户点击停止按钮结束任务流程，此时停止数据收集并自动收起，用户
可手动点击卡片头部或「展开」按钮，点击后卡片变为「展开态」，收集状态变为“已停
止搜索和分析资料”，交互和已完成状态一致

组件交互
搜索内容默认展示2行，超出部分收起，用户可手动展开

简易版收集组件构成
在部分场景不需要强调收集数据的过程，可用简化版组件，由icon、内容和指示箭头三
部分构成

1、示意icon：可选，表示“收集”
2、内容：必有，收集的所有资料，用户可点击，点击后查看详情，可用其他容器承载具

体信息，根据业务场景处理即可
3、指示箭头：可选，根据业务场景自定义

使用场景示意
在思考过程中的数据收集场景

窄屏适配
常规布局标题字号14号字，内容区12号字；紧凑布局标题字号12号字，内容区12号字

### 规范文本
深度思考
智能体分析用户输入的内容并将其复杂推理过程可视化呈现

何时使用
用户选择深度思考模式并发出指令后，智能体调用深度思考功能对用户指令进行分析和拆解时

组件构成
深度思考包括思考状态、展开收起按钮和思考内容3部分

1、思考状态：必有，随状态变化，包括思考中、已完成思考、已停止思考

3、思考内容：可选，收起态时不展示

思考中

击后卡片变为「展开态」，思考状态变为“已完成思考”，已完成状态不限制卡片高度

已停止
智能体输出思考内容时用户点击停止按钮结束任务流程，此时思考内容输出停止并自动收起，用
户可手动点击卡片头部或「展开」按钮，点击后卡片变为「展开态」，思考状态变为“已停止思
考”，交互和已完成状态一致

组件交互
思考中默认展开，卡片高度随文字内容高度变化，用户可手动点击收起；已生成默认收起，用户
可手动点击展开

窄屏适配

## 状态栏

### 审核方式
- 仅当被审核图片中出现「状态栏」或其同类 Agent 组件时适用。
- 优先检查规范文本中的「必有」项、状态文案、展开/收起交互、主次操作和容器高度。
- 规范写明「可选」的元素不能因为缺失直接判定违规；只有业务场景需要但设计缺失时才作为问题。
- 标题加示意图的页面代表该状态或结构的标准视觉参考。没有明确尺寸标注时，不要把示意图中的像素值当作硬性尺寸。

### 规范文本
状态栏
对话场景中透传任务进度及服务引导，让用户可以清晰感知到当前任务的进展

何时使用
底部状态栏固定于 Agent 任务界面底部，贯穿任务执行前、执行中及执行后全流程，以一致的可
视化形式实现全周期状态透传，并聚合全局性操作入口功能（如暂停、终止、返回上一步等）

基础状态栏
任务执行中
任务执行过程中的状态栏结构较为固定，与流程无关的操作和信息通知尽量都在状态栏中呈现

1、状态符号：必有，有静态和动态2种状态，任务执行中为动态图标，任务执行前后，或需用户
操作的场景为静态图标
2、描述文案：必有，执行中的通用文案由【正在运行中】+【任务耗时】组成
3、终止按钮：必有，点击后出现2次确认弹窗

拓展状态栏
任务执行过程中的状态栏结构较为固定，与流程无关的操作和信息通知尽量都在状态栏中呈现

1、AI符号：必有，有静态和动态2种状态，任务执行中为GIF图标，任务执行前后，需用户操作
的阶段为静态图标

## 扩展审核规则

### 来源类型

- `pdf_text`：来自 `references/B-design/` PDF 的明文标题、正文、必有/可选项、状态说明。
- `pdf_visual_example`：来自 `references/B-design/` PDF 中只有标题、状态名或示意图的页面。可归纳组件结构、层级、状态视觉和常见摆放方式；不要归纳精确像素、未标注 token 或未出现的交互。
- `alpha_case`：来自 `references/alpha/` 红字审核案例。此类规则用于补足 B-design 审核必须检出的历史问题；只在截图命中相同页面场景或相同可见视觉模式时使用。

### PDF 示意图归纳规则

- 示意图中的组件外观可作为同名组件或同名状态的视觉参考，包括容器边界、标题位置、内容区层级、展开收起入口、主次按钮区和状态图标位置。
- 生成中卡片类示意图均表现为「卡片标题 + 内容主体 + 主按钮/次按钮 + 延展操作」的单一任务容器，不应把确认区、内容区和延展操作拆成多个互不关联的外层容器。
- 任务规划、任务节点、数据收集、深度思考等组件的状态图标、状态文案和展开收起入口应共同表达同一任务阶段；示意图中没有出现的装饰性图形、emoji 或营销式图标不能自行加入。
- 示意图中常见的浅灰背景、白色内容面、分隔线和圆角用于表达层级，不代表可以无限嵌套。审核时应重点看层级是否清楚、是否过度包裹，而不是臆造精确间距。
- 当 PDF 页面只有状态标题和示意图时，状态标题是规则语义，示意图是视觉参照；问题输出的 `rule_source_type` 标为 `pdf_visual_example`，`rule_source_ref` 标明对应组件和状态。

### alpha 案例沉淀规则

- 操作按钮顺序：保存、预览确认、确认、下一步等推进类动作放在左侧；取消类动作放在右侧。若保存与下一步表达同一动作，只保留一个主动作，并放在下一步/确认的位置。来源：`image.png_4_c1Yd 1.png`、`image.png_5TlY3c 1.png`、`image.png_NDR-SQ 1.png`、`image.png_J7f9j- 1.png`。
- 底部按钮区：按钮样式、尺寸、间距和位置应跟模板一致；不必所有按钮都吸底，若主体内容较短，可放在灰框或内容容器下方。来源：`image.png_5mvbDV 1.png`、`image.png_Bgn1SM 1.png`、`image.png_J7f9j- 1.png`、`image.png_wpWnCq 1.png`。
- 色彩语义：AI、智能生成、诊断、勾选等模板明确指向智能能力的控件可使用紫色；普通非 AI 功能、传统表单、订单/打单/配置类主按钮不要使用紫色，应按 B 端常规主按钮蓝色处理。来源：`image.png_FaeyIY 1.png`、`image.png_a3UXmh 1.png`、`image.png_bmRvcc 1.png`、`image.png_PdZ0hi 1.png`。
- 禁止误用状态色：不可点击内容不要使用蓝色链接态；非破坏/失败语义不要用红色；完成态不要随意使用绿色勾，除非该场景模板明确需要。来源：`image.png_-a8rBX 1.png`、`image.png_SXaovH 1.png`、`image.png_mUmMDx 1.png`。
- 选中态：列表、预览、传统 B 端选择态按模板使用蓝色；AI 表单或模板中明确的勾选框选中态可用紫色。不要把蓝、紫、绿混用成多个竞争的选中/完成信号。来源：`image.png_NDR-SQ 1.png`、`image.png_PdZ0hi 1.png`、`image.png_mUmMDx 1.png`。
- 容器层级：不要出现灰卡套白卡再套灰卡的三层嵌套；一般最多两层。灰框外不要再套无意义白框，参考模板时应把内容包在模板灰卡内。来源：`image.png_NDR-SQ 1.png`、`image.png_R1tkjo 1.png`、`image.png_SXaovH 1.png`、`image.png_wpWnCq 1.png`、`image.png_zdYc6Q 1.png`。
- 卡片留白和边框：容器应保留足够内边距，边框和背景层级要清晰；不要让内容贴边、边框过重或卡片之间层级不明。来源：`image.png_PuU9v7 1.png`、`image.png_XESn9B 1.png`。
- 图标规则：图标尺寸跟模板一致，不要过大；首页入口、诊断卡片、AI 卡片图标应使用模板图标。不要使用无依据星星、emoji 或装饰性图标。来源：`image.png_Hhc744 1.png`、`image.png_oLzlqU 1.png`、`image.png_wpWnCq 1.png`、`image.png_MZxI2s 1.png`、`image.png_PdZ0hi 1.png`。
- 下拉和输入框：没有下拉选择语义时去掉下拉箭头；输入框结构、边框、占位区域和按钮组合参考模板，不要自造不同层级。来源：`image.png_l_Vf4O 1.png`、`image.png_R1tkjo 1.png`。
- 对齐和标题：普通页面元素应对齐到同一视觉网格；标题优先放在内容左侧或模板指定位置，不要因卡片/按钮错位造成扫描负担。来源：`image.png_5mvbDV 1.png`、`image.png_wpWnCq 1.png`、`image.png_PdZ0hi 1.png`。
- 渐变和高亮：除模板明确要求外，不建议使用大面积渐变；黄色背景和描边应弱化或去掉，避免与风险/提醒语义混淆。来源：`image.png_TS5eSK 1.png`、`image.png_XESn9B 1.png`。

### 扩展规则输出要求

- 使用本章节输出问题时，每个 issue 必须写明 `rule_source_type` 和 `rule_source_ref`。
- `rule_source_type` 只能取 `pdf_visual_example` 或 `alpha_case`；若来自 PDF 明文规则，则取 `pdf_text`。
- `rule_source_ref` 应包含组件/状态名或 alpha 文件名，便于报告追溯。
- 如果只观察到风格相似但无法确认是否同一场景，把结论写入 `cannot_verify`，不要输出违规。
